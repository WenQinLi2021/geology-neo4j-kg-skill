# Geology Neo4j KG Skill 技术文档

## 1. 文档目标

本文档说明如何在团队内安装、触发、使用和维护 `geology-neo4j-kg` skill。

该 skill 适用于以下场景：

- 从 PDF、OCR、Word、网页资料中抽取地质知识
- 构建稀土、三稀、稀散元素、成矿带等主题知识图谱
- 将抽取结果整理为 `JSON -> 规范化 -> Neo4j Cypher`
- 在 Neo4j Desktop 或 Aura 中持续增量更新知识图谱

## 2. Skill 功能范围

该 skill 固化了一个证据链驱动的知识图谱流水线：

1. 先锁定本体与抽取契约
2. 再按批次抽取实体、关系、属性、证据链
3. 然后做别名归并、去重、冲突标记、规范化
4. 最后导出可导入 Neo4j 的 Cypher

它不是“整份 PDF 一键自动入库”的黑箱工具，而是一个面向团队复用的人机协作工作流。

## 4. 安装方式

### 4.1 默认安装

在本仓库根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install_skill.ps1
```

默认安装到：

```text
C:\Users\<用户名>\.codex\skills\geology-neo4j-kg
```

### 4.2 指定安装目录

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install_skill.ps1 `
  -TargetRoot "D:\TeamCodexSkills"
```

安装后目标目录将变为：

```text
D:\TeamCodexSkills\geology-neo4j-kg
```

## 5. 使用方式

### 5.1 典型触发词

以下任务适合显式调用该 skill：

- “继续处理这批稀土科研报告，抽取并导出 Neo4j Cypher”
- “请先设计地质知识图谱的最小本体，再开始抽取”
- “将这批抽取 JSON 融合到现有 normalized graph”
- “只导出高置信度、低争议事实型知识”

### 5.2 推荐显式调用模板

```text
Use $geology-neo4j-kg.
继续处理这批地质科研报告，按当前 schema 抽取、融合、保留 review_flags，并导出 Neo4j Desktop 可直接导入的 Cypher。
```

### 5.3 分阶段调用模板

#### A. 先定本体

```text
Use $geology-neo4j-kg.
请先设计这个项目的最小本体，目标是 2 周内能导入 Neo4j 的 v1。
输出实体类、关系类、唯一键、证据字段和抽取粒度。
```

#### B. 正式抽取

```text
Use $geology-neo4j-kg.
按当前 schema，从这批报告中抽取实体、关系、属性和证据链。
输出 JSON，不要解释。
```

#### C. 融合规范化

```text
Use $geology-neo4j-kg.
把这些 extraction JSON 融合到现有 normalized graph。
统一规范名，合并别名，保留冲突项到 review_flags。
```

#### D. Neo4j 导出

```text
Use $geology-neo4j-kg.
基于 merged normalized JSON，导出高置信度、低争议的 Neo4j Cypher。
同时输出导出摘要。
```

## 6. 推荐项目目录

建议项目统一采用如下结构：

```text
project/
  schema/
  sources/
  extractions/
  normalization/
  neo4j_export/
```

含义如下：

- `schema/`
  本体、JSON schema、字段规范
- `sources/`
  原始报告
- `extractions/`
  按批次抽取出的 JSON
- `normalization/`
  融合、规范化、去重后的主图谱文件
- `neo4j_export/`
  导出的 Cypher、CSV、导入脚本、摘要文件

## 7. 标准工作流

### 7.1 阶段一：锁定规则

在计划模式中先确认：

- 图谱目标
- 本体最小集
- 命名规范
- 证据链字段
- 抽取粒度
- 入库策略

### 7.2 阶段二：批量抽取

按 `1-3` 份同主题报告为一批处理，避免一次性主题过散。

每批应输出：

- 批次 extraction JSON
- 基本质量判断
- 疑似低置信度项

### 7.3 阶段三：融合与规范化

应完成：

- 别名归并
- 同名消歧
- 去重
- 跨报告证据合并
- review_flags 标记

### 7.4 阶段四：导出

默认推荐只导出：

- 实体置信度 `>= 0.90`
- 关系置信度 `>= 0.90`
- 未被 `review_flags` 命中的事实
- 可形成连通子图的实体

## 8. review_flags 机制

`review_flags` 用于显式保留不确定项，不直接入首轮 Neo4j 图谱。

常见触发条件：

- 关系方向不清晰
- 规范化存在歧义
- 多个来源冲突
- 句子更像研究推断而非已验证事实
- 置信度低于预设阈值

推荐策略：

- 先入高置信度事实
- 把 `review_flags` 项延后，由专业人员二次复核

## 9. Neo4j 导出脚本

导出脚本路径：

[`skills/geology-neo4j-kg/scripts/build_neo4j_cypher.py`](../skills/geology-neo4j-kg/scripts/build_neo4j_cypher.py)

主要功能：

- 从 merged normalized JSON 生成 Cypher
- 可设置实体和关系置信度阈值
- 可限制允许导出的谓词集合
- 可排除 `review_flags`
- 可生成 Neo4j 中文显示字段更新脚本
- 可输出 summary JSON

示例命令：

```powershell
python ".\skills\geology-neo4j-kg\scripts\build_neo4j_cypher.py" `
  --input-json "C:\path\to\roundX_merged_normalized.json" `
  --output-cypher "C:\path\to\roundX_high_confidence.cypher" `
  --summary-out "C:\path\to\roundX_high_confidence_summary.json" `
  --display-zh-out "C:\path\to\roundX_display_zh.cypher" `
  --entity-confidence-min 0.9 `
  --relation-confidence-min 0.9 `
  --safe-predicates "belongsToUnit,locatedIn,hasDepositType,hostedIn,occursInProfile,partOfProfile,overlies,underlies,locatedOnInterface,formedByWeatheringOf,formedDuring,enrichedIn,containsMineral,occursAs,adsorbedBy,leachedFrom,carriesElement,hasAnomaly"
```

## 10. 团队协作建议

### 10.1 用户职责

- 提供原始科研报告
- 明确本批次主题边界
- 指定是否只要高置信度导出

### 10.2 Skill / Codex 职责

- 读取报告
- 按 schema 抽取知识
- 进行规范化和融合
- 维护 review_flags
- 生成 Neo4j 可执行导出

### 10.3 批次建议

最稳的节奏不是“一篇一篇直接入库”，而是：

- 每次积累 `1-3` 份同主题报告
- 先抽取
- 再融合
- 再统一导出增量 Cypher

## 11. 运维与版本维护

建议每次本体或导出规则发生变化时，更新以下内容：

- `skills/geology-neo4j-kg/SKILL.md`
- `references/schema.md`
- `references/workflow.md`
- `references/prompt-templates.md`

如果导出规则变化，务必重新测试：

- 节点数量是否异常
- 关系数量是否异常
- 是否有语法错误
- 是否错误导入了低置信度或争议知识

## 12. 当前限制

- 该 skill 主要固化了工作流和导出规则，不代替领域专家判断
- 复杂地层命名冲突、成矿理论冲突仍需 review
- 如果团队要支持更多矿种，应继续演化 schema，而不是直接强套现有 rare-earth v1

## 13. 推荐团队起步方式

建议先做如下三步：

1. 安装本 skill
2. 用 `1-2` 批真实报告试跑
3. 根据实际领域扩展点调整 `schema.md`

当这三步稳定后，再把它作为团队的标准知识图谱生产模板。
